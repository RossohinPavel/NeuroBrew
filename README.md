# NeuroBrew

Сварим крафтуху вместе с нейроновыми.


## Идея

Удаленый репозиторий для правил, скилов для нейронок и агентов.
Разделение бекенд, фронтенд. Фронт на некстжс, там все конфигурируем. Бекенд NestJs + fastify адаптер - обслуживает мсп подключения. Скорее всего, нужно будет shared-библиотеку для базы данных. 


# Логика авторизации

1. ХРАНЕНИЕ ТОКЕНОВ (COOKIES)
   • access_token: Доступен везде (path: '/'). Живет 15 минут.
   • refresh_token: Скрыт за path: '/api/auth/refresh'. Живет 7 дней. Браузер шлет его только туда.

2. СЦЕНАРИЙ 1: ПОЛЬЗОВАТЕЛЬ ОТКРЫЛ ЗАКЛАДКУ (СЕРВЕРНЫЙ ПЕРЕХОД)
   • Браузер запрашивает Server Component страницы (например, /dashboard).
   • Страница видит протухший Access и делает HTTP-редирект (307) на /api/auth/refresh?callbackUrl=/dashboard.
   • Браузер на сетевом уровне (без рендера) идет на рефреш, отдает Refresh-куку и обновляет токены через Set-Cookie.
   • Эндпоинт рефреша возвращает пользователя на /dashboard. Страница открывается без миганий интерфейса.

3. СЦЕНАРИЙ 2: ПОЛЬЗОВАТЕЛЬ КЛИКАЕТ ПО ИНТЕРФЕЙСУ (КЛИЕНТСКИЙ FETCH)
   • Клиентский JS делает запрос за данными. API-эндпоинт возвращает статус 401 Unauthorized.
   • Кастомный перехватчик (интерцептор) ловит 401 ошибку и в фоне делает fetch('/api/auth/refresh').
   • Браузер автоматически прикрепляет Refresh-куку, сервер обновляет токены в Set-Cookie.
   • Интерцептор ловит успешный ответ от рефреша и автоматически повторяет исходный запрос за данными.

4. СЦЕНАРИЙ 3: ПОЛНЫЙ РАЗРЫВ СЕССИИ (ТОКЕНЫ СДОХЛИ)
   • Если на шаге 2 или 3 эндпоинт /api/auth/refresh видит, что Refresh-токен невалиден или отсутствует.
   • Сервер делает жесткий редирект (или возвращает команду) на перенаправление пользователя на страницу /login.

Краткое техническое саммари вашей архитектуры без Middleware:

* Логика в лейаутах (layout.tsx): Защита привязана к структуре папок приложения. Проверки выполняются на сервере до рендеринга страниц, исключая «мигание» контента.

* Своя логика для каждого маршрута:
  - Зона авторизации (auth/layout.tsx): Гостевой Guard. Если токен валиден — жесткий redirect в профиль. Защищает /auth/login, /auth/register и т.д.
  - Приватная зона ((protected)/layout.tsx): Приватный Guard. Если токена нет — жесткий redirect на логин. Автоматически защищает /settings и все вложенные папки.
  - Динамическая зона (/[username]/[projectname]/page.tsx): Мягкая локальная проверка внутри страницы (сравнение владельца из БД и текущей сессии).
  - Корень сайта (/): Мягкая проверка в page.tsx. Если юзер есть — отдаем дашборд, если нет — лендинг.

* Производительность: Проверка JWT (getSession) обернута в React.cache. Сколько бы компонентов (лейаут, меню, страница) ни вызывали сессию в рамках одного запроса, JWT парсится строго один раз в оперативной памяти (RAM) сервера.

* Тонкий роутер: В папке app лежат файлы-пустышки в 1 строку, которые просто реэкспортируют рабочие лейауты и страницы из папки features.

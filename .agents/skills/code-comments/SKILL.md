# Code Comments

- Describe the action of the commented unit in clear human language so it remains understandable without reading its implementation.
- Document abstractions through their purpose, contract, responsibilities, guarantees, and constraints. Describe implementation details through the abstraction they fulfill or support; do not define an abstraction by its implementation.
- Mention implementation details only when they are part of the contract or directly affect behavior. Explain syntax or mechanics only when necessary to understand the action.
- Include domain or real-world context only when it clarifies a non-obvious constraint, relationship, or reason. Do not invent domain meaning for general-purpose code.
- Prefer precise domain terms when domain context matters; otherwise use direct technical language. Avoid vague descriptions that merely restate a unit's name.
- Follow the language, project, surrounding-code, linter, and documentation conventions for comment style.
